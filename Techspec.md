## Framework choice

**HTML custom elements (`@videojs/html`) + Vite, no UI framework.**

- The challenge is about the skin, and HTML skins are framework-neutral: the same markup works in plain HTML, Vue and Svelte (the v10 docs route all three through `@videojs/html`).
- `skin create --framework html` generates exactly this: `src/video/skin.html` (markup) + `skin.ts` (element registration) + CSS, with a Vite workbench.
- The gallery is a **Vite multi-page app**. Each route is its own HTML entry, so a skin page ships only its own skin's CSS and JS.
- React/Next was considered (docs default template) and dropped: it adds a runtime the judges don't need, and the skins would be React-only.

## How a skin renders

```
<video-player poster="…">                     ← @videojs/html/video/player (state + features)
  <media-container class="media-skin" data-theme="scaffold" data-preset="video" data-skin="phatta">
    <video src="…" playsinline crossorigin>   ← media, injected at the placeholder comment
    <media-poster> <media-error-dialog> <media-controls> … <media-hotkey> <media-status-announcer>
  </media-container>
</video-player>
```

- `data-theme="scaffold"` keeps the Scaffold's base tokens and layout working.
- `data-skin="<slug>"` is the hook for each skin's own CSS, so five skins never collide.
- Skins import their tokens in order: Scaffold CSS → `@panj/tokens` → `src/tokens.css`.

## Constraints

- Art in inline SVG + CSS only; it must scale from 320 to 1440 px and follow tokens.
- Animation only through `--panj-motion-*`, which drop to 0 under `prefers-reduced-motion`.
- `backdrop-filter` (Glass) must have a solid fallback.
- Keep the Scaffold's error dialog, hotkeys and status announcer.
- Support the public `--media-*` props wherever the art allows.
